# Audit v1.2.0 — Comportement visible par l'utilisateur

Racine : `microsoft-store/` (dépôt git autonome). Plage auditée : `452aab0^..HEAD` (`ad049fc`..`697d1a3`), 23 commits, 115 fichiers, +17 840/-1 946.

## Avertissement méthodologique — la base `ad049fc` n'est pas un vrai « v1.1.0 »

Le premier commit de la plage, `452aab0` (« refactor: reconcile v1.2 and extract typing core »), n'est pas un commit de fonctionnalité : c'est un **rapatriement en bloc** de la base interne 1.1.2 et des fonctions 1.2.0 en développement dans le dépôt public canonique (Changelog.md ligne 7). Preuve : `git show 452aab0:src/Program.cs` donne déjà `Version = "1.1.2"`, alors que `ad049fc` (le commit juste avant) donne `"1.0.0"` — le vrai « avant » que le Changelog décrit (1.1.2) n'est PAS ce que montre un diff brut contre `ad049fc`. Autre preuve : `src/UsageStatsWindow.cs`, `src/Localization/*.cs`, `src/ToastActivation.cs`, la détection `CompatibilitySuspendReason` existent déjà intégralement à `452aab0`, avec zéro changement supplémentaire entre `452aab0..HEAD` — donc antérieurs aux décisions datées du 2026-08-16/17 que le Changelog attribue à la v1.2.0.

Conséquence pour ce rapport : chaque fois que c'était vérifiable, j'ai identifié le commit réel qui a introduit un comportement (`git log -S 452aab0..HEAD`) plutôt que de me fier au diff brut contre `ad049fc`. Les tableaux ci-dessous portent une colonne « Depuis » quand c'est utile. Les 22 commits de `452aab0..HEAD` sont datés du 2026-08-15 au 2026-08-17 ; ceux du 2026-08-16/17 correspondent bien aux décisions que le Changelog cite par date.

## § Points à vérifier à la main

Chaque étape suppose une installation packagée (MSIX) sauf mention contraire.

1. Toujours-visible "Défi du jour" : installer proprement (aucune config existante), ouvrir le menu tray sans avoir jamais coché aucun opt-in. Résultat attendu : l'entrée "Défi du jour" est présente dès le premier lancement.
2. Bouton de partage conditionnel : dans Leçons, terminer une leçon de la séquence de désapprentissage (les 5 premières après le Défi). Résultat attendu : pas de bouton "Copier mon résultat" sur son récapitulatif. Puis terminer le Défi commun du jour. Résultat attendu : le bouton apparaît sur ce récapitulatif-là uniquement.
3. Record personnel : rejouer deux fois le Défi du jour en tapant plus vite la seconde fois. Résultat attendu : la mention de nouveau record dans le texte copié au second essai, absente au premier.
4. Annonce qui ouvre la séance, pas les Paramètres : sur une install migrée depuis un état pré-1.2.0 (opt-in entraînement désactivé, annonce jamais faite), démarrer l'app sans passer par l'accueil. Résultat attendu : une notification "Nouveau : Défi du jour" apparaît une fois ; cliquer dessus ouvre directement la séance du jour, pas les Paramètres.
5. Autostart coché = réalité, pas cache : cocher "Lancer au démarrage de Windows" depuis le menu, puis supprimer manuellement le raccourci de démarrage ou désactiver la tâche associée en dehors de l'application. Rouvrir le menu tray. Résultat attendu : la case n'est plus cochée, parce que l'état lu est l'inscription réelle et non un booléen mis en cache.
6. Relance autostart à J+2 d'usage réel, pas J+2 calendaire : installer, ne pas cocher l'autostart à l'accueil, taper avec l'app un jour, ne pas l'ouvrir le lendemain, la rouvrir le surlendemain (2e jour d'usage). Résultat attendu : une seule proposition de lancement automatique apparaît à ce moment, jamais avant, jamais une seconde fois ensuite.
7. Report de l'avis derrière l'accueil : configurer l'app pour que l'accueil s'affiche à chaque démarrage et atteindre artificiellement les seuils du premier essai (3 jours d'usage).
