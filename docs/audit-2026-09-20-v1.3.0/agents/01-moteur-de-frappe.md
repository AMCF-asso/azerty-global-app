Chemins relatifs à `src/` sauf mention contraire. Citations littérales, ≤ 2 lignes.

Fait de cadrage utile à tout le rapport : `Install()` est appelé depuis `LoadAndStart()`
(`TrayApplication.cs:338`), sur le thread qui porte la boucle de messages
(`TrayApplication.cs:546`). Le callback du hook LL, les callbacks WinEvent (`WINEVENT_OUTOFCONTEXT`)
et tous les `WM_TIMER` s'exécutent donc **sur ce même thread**. Les seules autres exécutions
concurrentes du produit sont le worker UIA (`SecureInputDetector.cs:94`) et l'append de log
(`ConfigManager.cs:731`).

## Non vérifié

1. **Comportement runtime de Windows** — rien n'a été exécuté (lecture seule, pas de VM). Tout ce qui concerne l'acceptation réelle des `INPUT` par une application tierce (`KEYEVENTF_SCANCODE`, Alt+code, combo AltGr) reste hors de portée ; `TestSupport/MockWin32Api.cs:4-11` liste d'ailleurs ces limites comme non testables par construction.
2. **Valeur de `LowLevelHooksTimeout`** sur les postes cibles : non lue (clé `HKCU\Control Panel\Desktop`), et aucun code de l'application ne la lit non plus. La durée réelle du chemin le plus long (§ 1) n'a donc pas été comparée à un seuil.
3. **Cause certaine de l'écart 5** : § 8.3 et § 8.5 décrivent deux mécanismes que le code rend possibles et qui collent aux signatures relevées (`@` muet, touche morte perdue, même geste deux résultats). Aucun des deux n'est prouvé sans instrumentation ; ils sont proposés comme hypothèses à départager en session de débogage, pas comme diagnostic.
4. **Slots vtable UIA** (`SecureInputDetector.cs:32-33`, 8 et 35) : non recoupés contre `UIAutomationClient.h` — le commentaire dit SDK 10.0.26100.0, je n'ai pas ouvert l'en-tête.
5. **Affinité de thread réelle** du callback LL : déduite du site d'appel de `SetWindowsHookEx` et de la boucle de messages, jamais observée à l'exécution. Toute la section 9 dépend de cette déduction.
6. **Couverture réelle des tests** : les noms ont été relevés par lecture, la suite n'a pas été exécutée. Aucun test n'instancie `KeyboardHook` ni `SecureInputDetector` — les cases « aucun trouvé » du rapport signifient « aucun test portant ce nom ou ce sujet dans les quatre projets de test lus », pas « non couvert par un run ».
7. **Branche vs version** : `git branch --show-current` rend `release/1.2.0-notation-store` alors que le candidat est annoncé v1.3.0 ; je n'ai pas instruit cet écart de nommage, hors périmètre.
